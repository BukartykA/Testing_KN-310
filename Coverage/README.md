# Звіт до роботи
## Тема: Покриття коду (Code Coverage)
## Мета роботи: Навчитися вимірювати покриття рядків (line coverage) та розгалужень (branch coverage) за допомогою бібліотек `coverage.py` і `pytest-cov`, налаштовувати конфігурацію через `.coveragerc`, генерувати звіти у текстовому, HTML та XML форматах, а також розуміти обмеження метрик покриття.

## Виконання роботи

### 1. Встановлення інструментів
Для вимірювання покриття коду встановлено `coverage`, `pytest` та плагін `pytest-cov`:
```bash
py -m pip install coverage pytest pytest-cov
```

### 2. Порівняння окремих запусків `unittest` та `pytest` (покриття до і після додавання тестів)
1. **Запуск тестів `unittest` (`test_unittest.py`)**, де перевіряється лише трикутник:
```bash
py -m coverage erase
py -m coverage run -m unittest discover
py -m coverage report -m
```
Результат до додавання тестів для квадрата і прямокутника:
```text
Name     Stmts   Miss Branch BrPart  Cover   Missing
----------------------------------------------------
app.py      18      1      4      2    86%   21, 20->21, 22->24
----------------------------------------------------
TOTAL       18      1      4      2    86%
```
**Пояснення пропущених рядків:** до додавання тестів для квадрата та прямокутника в `get_angles` виконувалася лише перевірка трикутника, тому гілка `if self.type in ["квадрат", "прямокутник"]: return 4` (рядок 21) не виконувалася жодного разу, а переходи `20->21` та `22->24` залишилися частково покритими (`BrPart = 2`).

2. **Запуск повного набору тестів `pytest` (`test_app.py`)**, де протестовано всі фігури (`квадрат`, `прямокутник`, `трикутник`) та невалідні вхідні дані:
```bash
py -m coverage erase
py -m coverage run -m pytest
py -m coverage report -m
```
Результат після додавання тестів:
```text
Name     Stmts   Miss Branch BrPart  Cover   Missing
----------------------------------------------------
app.py      18      0      4      0   100%
----------------------------------------------------
TOTAL       18      0      4      0   100%
```

3. **Перевірка мінімального порогу покриття через `pytest-cov` (`--cov-fail-under=90`):**
```bash
py -m pytest --cov=app --cov-branch --cov-report=term-missing --cov-fail-under=90 -v
```
Команда успішно пройшла перевірку порогу 90%, підтвердивши 100% покриття рядків та гілок модулем `app.py` (тестові файли виключені зі звіту завдяки налаштуванням `source = .` та `omit = test_*.py` у `.coveragerc`).

### 3. Різниця між покриттям рядків (Line Coverage) та покриттям розгалужень (Branch Coverage)
- **Покриття рядків (`Line / Statement Coverage`)** показує, чи був виконаний кожен виконуваний рядок коду хоча б один раз під час тестування.
- **Покриття розгалужень (`Branch Coverage`)** перевіряє, чи пройшли тести кожен можливий напрямок умовних переходів (`if` у гілку `True` та в гілку `False`). Навіть якщо рядок з `if` виконався (100% line coverage для цього рядка), гілка може бути покрита лише на 50%, якщо умова жодного разу не набула іншого логічного значення.

### 4. Використання `# pragma: no cover`
У файлі `app.py` позначку `# pragma: no cover` використано у двох місцях:
1. Для блоку `if __name__ == "__main__":`, оскільки це точка входу для ручного запуску скрипта, яка не є частиною бізнес-логіки, що тестується.
2. Для захисного рядка `return 0` у властивості `get_angles`: оскільки конструктор `__init__` гарантує через `assert type in self.FIGURES`, що об'єкт не може бути створений із невідомим типом фігури, цей резервний `return 0` є недосяжним при штатній роботі класу. Його виключення не спотворює оцінку важливої логіки.

### 5. HTML та XML звіти і їх призначення
Згенеровано звіти обох форматів:
```bash
py -m coverage html
py -m coverage xml
```
- **HTML-звіт (`htmlcov/index.html`)** призначений для людей (розробників і тестувальників): він відкривається у браузері та візуально підсвічує зеленим виконані рядки, червоним — пропущені, а жовтим — частково пройдені розгалуження.
- **XML-звіт (`coverage.xml`)** призначений для автоматизованих інструментів та CI/CD систем (наприклад, GitHub Actions, SonarQube, Codecov), які парсять цей файл для перевірки порогу покриття та відображення статусу у Pull Request.

### 6. Чого не доводить 100% покриття коду
<< Якщо написати тест, який просто викликає `Figure("квадрат", 4).get_angles` без оператора `assert`, `coverage.py` зафіксує виконання рядків та гілок і покаже високий відсоток покриття. Однак такий тест не перевіряє, чи повернув метод правильне число `4` (він міг повернути `999` або `None`, і тест усе одно пройшов би). Додавання `assert obj.get_angles == 4` гарантує не лише факт виконання коду, а й коректність результату. Отже, 100% line coverage свідчить лише про відсутність «мертвого» чи неперевіреного коду, але не гарантує відсутності логічних помилок або неврахованих граничних випадків. >>
