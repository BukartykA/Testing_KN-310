### 3. Взаємодія компонентів у реалізованих тестах
1. **Тести файлової системи (`test_export_and_load_tasks`, `test_export_empty_list`, `test_load_corrupted_json`):** перевіряють взаємодію функцій серіалізації/десеріалізації (`export_tasks`, `load_tasks`) із тимчасовою файловою системою (`tmp_path`), зокрема запис порожнього списку та обробку пошкодженого JSON-файла (`ValueError`).
2. **Тести бази даних (`test_init_db_creates_table`, `test_two_tasks_order_in_db`):** перевіряють взаємодію вебмаршруту `POST /tasks`, SQL-запитів та рушія SQLite, підтверджуючи створення таблиці `tasks` та збереження правильного порядку записів (`ORDER BY id ASC`).
3. **Тести HTTP-маршрутів (`test_create_task`, `test_get_tasks_status_200`, `test_create_task_without_title_returns_400`):** перевіряють повний наскрізний ланцюжок: тестовий клієнт Flask приймає JSON-запит, бізнес-логіка виконує валідацію (повертаючи `400 Bad Request` без поля `title` або `201 Created` при успіху), дані записуються в SQLite та експортуються у JSON-файл.
4. **Інтеграційний тест видалення (`test_delete_task_integration`):** перевіряє маршрут `DELETE /tasks/<int:task_id>`, синхронне видалення запису з таблиці SQLite, перезапис JSON-файла актуальним списком завдань та повернення статусу `404 Not Found` для неіснуючого ID.

### 4. Фрагмент коду перевірки HTTP-відповіді, SQLite та JSON-файла
```python
def test_create_task(test_env):
    client, db_file, json_file = test_env

    # 1. Перевірка HTTP-відповіді
    response = client.post("/tasks", json={"title": "Вивчити pytest"})
    assert response.status_code == 201
    assert response.get_json() == {"id": 1, "title": "Вивчити pytest"}

    # 2. Перевірка фактичного запису в SQLite
    conn = sqlite3.connect(db_file)
    row = conn.execute("SELECT id, title FROM tasks").fetchone()
    conn.close()
    assert row == (1, "Вивчити pytest")

    # 3. Перевірка експортованого JSON-файла
    exported = json.loads(json_file.read_text(encoding="utf-8"))
    assert exported == [{"id": 1, "title": "Вивчити pytest"}]
```
